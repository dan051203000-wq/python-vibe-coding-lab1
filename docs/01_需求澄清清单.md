# 需求澄清清单（Requirement Clarification Checklist）

> 本清单在把任务交给 AI 编码助手**之前**完成，用于明确目标、输入输出、边界与验收标准。
> 依据考核要求："先澄清需求再交给 AI"。

---

## 考题一：Excel 报表生成脚本

### 1. 目标
读取每月的销售原始数据 `sales_raw.xlsx`，完成数据清洗与统计汇总，输出标准化报表 `report.xlsx`，全过程不修改原始文件。

### 2. 输入规格
- 文件：`sales_raw.xlsx`（Excel 格式）
- 字段（6 列，均不可缺）：

| 字段 | 类型 | 说明 |
|---|---|---|
| 日期 | date/str | 交易日 |
| 销售员 | str | 人员姓名 |
| 产品 | str | 产品名 |
| 数量 | numeric | 销售数量，**可能为负数或 0（脏数据）** |
| 单价 | numeric | 单位价格 |
| 地区 | str | 销售大区 |

- 已知脏数据形态：**关键字段空值、完全重复行、数量 ≤ 0**

### 3. 处理规则（清洗）
1. 删除任一关键字段（6 个字段全部视为关键字段）缺失的行；
2. 剔除 `数量 <= 0` 的异常行；
3. 按**全字段**去重（6 列完全相同视为重复，保留第一条）；
4. **不得修改原始文件**（只读打开）。

### 4. 统计规格
- 销售额定义：`销售额 = 数量 × 单价`；
- 按销售员汇总：每个销售员的销售额合计；
- 按地区汇总：每个地区的销售额合计；
- 月度总额：清洗后全部数据的销售额总计。

### 5. 输出规格
`report.xlsx`，含 4 个工作表：
| Sheet 名 | 内容 |
|---|---|
| 明细清洗后 | 清洗后的全量明细（含销售额列） |
| 按销售员 | 销售员 → 销售额合计 |
| 按地区 | 地区 → 销售额合计 |
| 总览 | 月度总额、清洗前后行数等汇总信息 |

### 6. 边界与异常（必须处理，不可崩溃）
| 场景 | 预期行为 |
|---|---|
| 输入文件不存在 | 明确报错：文件路径 + 提示 |
| 文件不是合法 Excel / 空文件 | 明确报错，可读提示 |
| 缺少任一必需列 | 明确报错，列出缺失列名 |
| 清洗后无有效数据（0 行） | 明确提示"无有效数据"，不生成错误报表 |
| 清洗后仅剩极少量数据 | 正常出报表（统计维度自然变少） |

### 7. 验收标准
- [x] 样例数据一键运行生成正确 `report.xlsx`；
- [x] 统计数值与人工核对一致；
- [x] 异常输入不崩溃，报错信息可读（含场景定位）；
- [x] 原始文件字节级不变（校验 md5 前后一致）。

## 考题二：FastAPI 记账接口

### 1. 目标
实现一个可启动、可调用的记账 HTTP 服务，支持流水写入、筛选查询、区间汇总。

### 2. 技术选型决策（人工拍板）
- 存储：**SQLite**（而非内存）——理由：重启不丢数据；写入并发由 SQLite 事务串行化保证，便于回答"并发写入不产生数据错误"这一验收项；无需额外服务。
- 并发策略：每请求独立连接 + WAL 模式；写操作在事务内完成，SQLite 自带写锁保证原子性。

### 3. 数据模型
流水记录 Record：

| 字段 | 类型 | 约束 |
|---|---|---|
| 金额 amount | float | **必须 > 0** |
| 类型 type | str | 仅允许 `收入` / `支出` |
| 分类 category | str | 非空 |
| 日期 date | str | `YYYY-MM-DD` 格式，合法日历日期 |

### 4. 接口规格

**POST /records** 新增流水
- 成功：返回 `201` + 完整记录（含服务端生成的 id）；
- 失败：`400` + 结构化错误 `{"error": {"code": "...", "message": "...", "field": "..."}}`；
- 校验项：金额 > 0、类型合法、日期格式与合法性、分类非空。

**GET /records** 查询
- 可选筛选参数：`type`（收入/支出）、`category`、`start_date`、`end_date`（闭区间）；
- 分页参数：`page`（默认 1）、`page_size`（默认 20，上限 100）；
- 返回：`{"total": 总条数, "page": 当前页, "page_size": 每页条数, "records": [...]}`；
- 非法筛选参数（如 start_date > end_date、page < 1）→ `400` 结构化错误。

**GET /summary** 区间汇总
- 参数：`start_date`、`end_date`（可省略，省略即全部）；
- 返回：`{"income": 收入合计, "expense": 支出合计, "balance": 结余}`；
- 结余 = 收入合计 − 支出合计。

### 5. 边界与异常（测试必须覆盖）
| 场景 | 预期 |
|---|---|
| 金额 = 0 或负数 | 400 + 明确字段错误 |
| 类型为 "收支" 等非法值 | 400 |
| 日期 "2026-02-30"（格式对但日历不存在） | 400 |
| 日期 "2026/01/01"（格式错） | 400 |
| start_date > end_date | 400 |
| page=0 或 page_size=0 | 400 |
| 查询无结果的 summary | 200，合计为 0，不报错 |

### 6. 验收标准
- [x] 服务可启动（`uvicorn`）并正常调用；
- [x] 校验用例返回预期状态码；
- [x] pytest 覆盖核心用例（正常 + 边界/异常 ≥ 2 个）；
- [x] 并发写入说明：SQLite 事务 + WAL + 单写者模型（README 有专节说明）。

## 通用约束
- Python ≥ 3.10；依赖：pandas、openpyxl、fastapi、uvicorn、pytest、httpx；
- 所有代码可在本地一键运行：`pip install -r requirements.txt` 后按 README 指令执行；
- 原始数据只读，任何脚本不得写回输入文件。
